# ADR 0027：统一命令入口与可审计批量审查

- 状态：Accepted
- 日期：2026-07-16
- 决策范围：FR-04 操作入口与 FR-07 批量 Patch 审查

## 背景

五种内置 AI 操作已经能从编辑器工具栏发起，但缺少右键、键盘和命令面板入口。Patch 审查已经支持逐 hunk 接受/拒绝与原子应用，却要求用户逐项点击；已有“拒绝整个提案”是终止审查事件，不等价于为每个 hunk 形成明确的拒绝决策。

多个入口若各自维护操作列表、禁用规则和快捷键，会快速产生行为漂移。批量审查若只在页面一次性改写所有 decision，又会绕过 Store 的 revision、atomic group 和逐事件审计。

## 决策

1. 桌面端维护唯一 `AI_OPERATION_COMMANDS` 注册表，定义五种操作的 type、中文名称、说明与快捷键。工具栏、右键菜单、命令面板和全局快捷键全部从该表生成。
2. 可编辑 Block 的普通右键打开 AI 菜单；`Shift + 右键` 保留系统原生菜单。右键前先捕获当前 Block 与 UTF-16 选区，菜单重绘不能改变操作目标。
3. `Alt+1…5` 分别执行续写、润色、压缩、扩写、批评；`Ctrl/⌘+Shift+P` 打开可搜索命令面板。命令面板支持键盘搜索、Enter 执行、Escape 关闭；右键菜单支持方向键与 Escape。
4. Context 预览、模型执行或 Patch 审查期间，所有可能产生第二个并发操作的入口使用同一禁用条件。快捷键不会绕过界面禁用状态。
5. “全部接受/全部拒绝”先生成确定性的 decision plan。计划按 proposal hunk 顺序调用现有 `decidePatchHunk`；atomic group 在第一次决策时整体传播，后续成员不会产生重复事件。
6. 批量计划仍逐步调用 `append_review_event`，每一步携带前一 revision/status。只有 Host 持久化成功后页面才推进 session；中途失败时停在最后一个已确认 revision，可继续重试而不会伪造全量成功。
7. 全部拒绝后仍由用户点击“完成审查（不改正文）”产生最终 reject 事件；“放弃提案”继续作为不逐项决策、立即终止本候选的独立动作。

## 结果

- FR-04 的工具栏、右键、快捷键和命令面板入口共享同一行为与可用性规则。
- 批量审查保留逐 hunk 可追踪性、atomic group 语义和 Store 乐观并发，不增加新的高权限 IPC。
- 当前仍缺少跨会话的候选列表、重新打开未完成候选和“从候选建立分支”入口；这部分继续属于 FR-07 后续工作。

## 测试要求

- 单元测试覆盖 atomic group 只产生一个批量步骤、revision 连续递增和非法 decision 拒绝；
- 浏览器回归覆盖右键菜单、命令面板搜索、快捷键发起、Context 确认、全部接受和原子应用；
- 浏览器回归必须保持控制台与页面错误为空，并保存新入口和审查界面截图。
