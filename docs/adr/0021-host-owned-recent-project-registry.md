# ADR 0021：宿主维护的最近项目注册表

- 状态：Accepted
- 日期：2026-07-16
- 决策范围：欢迎页最近项目、机器级元数据存储与快速重开边界

## 背景

桌面应用此前只能让用户每次手工输入 `.optimizer` 绝对路径。把最近路径保存在 WebView `localStorage` 虽然实现简单，但页面脚本可以任意改写列表，且路径会与 Provider 偏好混在同一非权威存储中。把列表写进项目 SQLite 又会造成“一个项目保存其他项目路径”的错误所有权，并且在没有打开项目时无法读取。

最近项目只是一台机器上的便利索引。它不能替代 manifest、SQLite invariant、项目 ID、主分支与 HEAD 的真实性校验，也不能因为注册表损坏阻止用户通过显式路径打开项目。

## 决策

1. `RecentProjectRegistry` 位于 Tauri `app_local_data_dir`，独立于所有 `.optimizer` 包和 WebView 数据目录。直接 Rust 测试使用内存注册表或显式临时文件。
2. 注册表为严格 JSON：顶层与条目均 `deny_unknown_fields`，固定 schema version，文件不超过 256 KiB，最多 12 项；项目 ID、标题、语言、绝对路径和 RFC 3339 时间均受边界校验。
3. 创建或完整打开项目成功后，Host 按项目 ID 与目录双重去重，把该项目移到首位。写入使用同目录唯一临时文件并 `sync_all`，旧文件先移动到 `.bak`；发布失败恢复备份，启动时主文件缺失可读取备份。
4. 写最近记录是项目打开后的非关键便利副作用。注册表写入失败不会把一个已经通过校验的项目伪装成“打开失败”；应用启动配置注册表失败则拒绝创建主窗口，避免运行期处于未知机器级状态。
5. `list_recent_projects` 只返回注册表安全元数据和基于目录/manifest 存在性的 `available` 提示，不打开或迁移每个数据库。这个提示不是完整有效性结论。
6. 欢迎页快速打开只向 `open_recent_project` 提交 schema version 与稳定 `projectId`。Host 从注册表解析目录、调用 `OpenedProject::open` 完整校验，并额外确认实际项目 ID 与登记值一致后才建立 Session。
7. `remove_recent_project` 只移除机器级记录，绝不删除项目目录。缺失项目仍显示在列表中供用户显式移除。
8. 三个命令位于独立 `allow-recent-projects` permission；普通 `open_project` 仍保留，用于用户显式输入任意绝对项目路径。

## 失败与恢复语义

- 注册表 JSON 篡改、未知字段、超限或无效时间会被拒绝，不向页面暴露未经校验的记录。
- 临时写入或发布失败会回滚内存列表；旧主文件通过备份恢复。
- 注册路径被另一个项目替换时，快速打开返回绑定变化错误且不建立 Session。
- 项目目录缺失时列表标记不可用；记录不会被静默删除。

## 测试要求

- Host 覆盖持久化重载、项目/目录去重、排序、缺失路径、移除、未知字段与大小上限。
- Desktop 覆盖跨 State 重启重载、按项目 ID 快速打开、移除不删文件与 permission/manifest 完整性。
- 浏览器回归从关闭 Session 的欢迎页显示最近项目，快速打开后继续跑完整工作区、章节和 AI 审查流程。

## 后果

- 用户可以一键回到近期作品，且不削弱 `.optimizer` 项目包的完整校验边界。
- 注册表当前只支持单进程桌面实例。若未来允许多实例，应增加文件锁或单实例协调，而不能依靠最后写入覆盖并发变化。
- “收藏/固定项目”、路径迁移和系统文件选择器可以复用此边界，但需要显式扩展 schema 与交互，不能偷偷改变最近列表语义。
